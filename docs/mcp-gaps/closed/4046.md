# A border given a name but no type is folded away, name and all, so `match` cannot find it — **CLOSED** (#4046, 2026-11-16)

**Symptom (2026-10-22, #157, headless).** The designer's box for a control HexIDE does not model was a
`ClassicBorderDecorator` with `AutomationProperties.Name` set to the control's name. `dump_visual_tree`'s `match`
path, `UiAutomationDriver.Find(UiAutomationDriver.Dump(window, "Window", 60, interactiveOnly: false), "imlIcons", 10)`,
the code `{"match":"imlIcons"}` runs, found nothing. A border's control type is `None`, it has no provider and takes no
focus, so the control view hides it as plumbing, and the name it was given goes with it. This is the rule
[#1436](https://github.com/hexide-io/HexIDE/issues/1436) is about, reached from the other side: a name set on purpose is
no more plumbing than an AutomationId.

**Workaround.** Give the element a type: `AutomationProperties.ControlTypeOverride="Pane"` keeps it, as `VBProps` does
for a running form's Frame, PictureBox, Label and Image.

**Suggested fix (at discovery).** Count an explicitly set `AutomationProperties.Name` as the AutomationId already counts, so a view's
author is not left to discover the override. The path-stability part of #1436 is fixed; this explicit-name
discovery gap was still open then.

**Fix (#4046).** The control-view rule now keeps a control when
`control.IsSet(AutomationProperties.NameProperty)`, just as an explicit AutomationId keeps it.
A peer name derived only from content does not keep a structural wrapper. The existing
`interactiveOnly` filter still applies to tree dumps; `match` already searches every node, so
`dump_visual_tree {"match":"imlIcons"}` discovers a noninteractive leaf too. Its emitted path resolves
through the same collector used by `inspect_element`.

**Verification:** headless regression tests cover discovery, path resolution and inspection, unnamed
borders, and a peer name derived from content. **live check pending (hexide-mcp)**: discover the
designer's named unsupported-control box and inspect the returned path in the same window.

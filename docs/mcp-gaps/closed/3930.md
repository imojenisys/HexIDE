# activate_document_tab refuses a carried file by name — **CLOSED** (#3930, 2026-11-14)

Symptom, measured during #266's live check and recorded in [#3930](https://github.com/hexide-io/HexIDE/issues/3930): with `Module=snipmod; snipmod.cpp` carried by Live3904 and its tab open,
`open_file {name: "snipmod", line: 2, column: 16}` succeeded with tab `Live3904 - snipmod`, but
`activate_document_tab {name: "snipmod"}` refused: "No form or module named 'snipmod' in any loaded project: 'snipmod' is a carried file. Live3904 holds no forms and UserControls; modules Module1; carried files snipmod."
The description promised the same lookup as `open_file`. An unsaved caption, `Live3904 - snipmod *`, also failed as `title`, because the title omits the marker.

Workaround: `activate_document_tab {title: "Live3904 - snipmod"}` succeeded. Use the title from `get_document_tabs`, without the unsaved marker.

Fix: activation resolves `name` through `open_file`'s lookup, including carried files, retaining its module precedence and refusal with candidates and `project` for ambiguous carried files. It activates an existing tab and refuses a closed one, as it already does for modules. If an exact title has no match, activation accepts the trailing caption marker and explains that the title omits it. Exact titles and duplicate-title refusals retain priority.
